# Day 04 - Network Threat Hunting

## Objective

Investigate network-based alerts generated by Suricata IDS and identify the systems receiving the highest volume of suspicious traffic.

---

## Investigation 1 – Identify Most Targeted Hosts

### Query

```spl
index=botsv1 sourcetype=suricata event_type=alert
| top dest_ip
```

### Purpose

Determine which internal systems generated the highest number of IDS alerts.

### Findings

The analysis identified two primary targets:

| Destination IP | Observation |
|----------------|-------------|
| 192.168.250.70 | Highest volume of IDS alerts |
| 192.168.250.100 | Second highest volume of IDS alerts |

These hosts became the primary focus for additional investigation.

---

## Investigation 2 – Review High Severity Alerts

### Query

```spl
index=botsv1 sourcetype=suricata event_type=alert alert.severity=1
| table _time src_ip dest_ip alert.signature alert.category
```

### Purpose

Review only the highest severity IDS alerts to understand the nature of the detected attacks.

### Findings

- Multiple Severity 1 alerts were identified.
- Repeated alerts targeted the same internal systems.
- Several attack signatures appeared repeatedly throughout the dataset.

The alerts suggest sustained hostile network activity rather than isolated events.

---

## Investigation 3 – Examine Traffic Associated with Target Hosts

### Query

```spl
index=botsv1 dest_ip="192.168.250.70"
| stats count by sourcetype
| sort -count
```

### Purpose

Identify which telemetry sources contain activity related to the targeted host.

### Findings

Telemetry included:

- Suricata IDS Alerts
- HTTP Traffic
- TCP Traffic
- ICMP Traffic
- IP Traffic

The presence of multiple telemetry sources provides sufficient evidence for cross-source correlation in later investigations.

---

## Analyst Assessment

Network monitoring identified repeated IDS alerts against a small number of internal hosts.

Although the IDS generated numerous alerts, additional host-based evidence is required before confirming successful compromise.

The next step is to correlate these alerts with Windows authentication activity and endpoint telemetry.
